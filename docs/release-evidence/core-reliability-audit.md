# Rewind core reliability audit

**Decision:** The revised build performs the intended investigation for supported trusted Python scripts on a Mac. It captures evidence, reproduces a recorded failure, identifies a difference and lets a developer test a controlled intervention. This qualifies the exercised local alpha workflow. The evidence for a supported beta or a public multi-user deployment is incomplete.

This pass used installed wheels, Chrome, the public CLI, disposable SQLite stores, an independent HTTP request counter and actual local Ollama inference. The initial build was `4e134b3`. The final installed wheel SHA-256 was `04e9ab9b55f682a78ff7c7cf6bc5a20fb1216f62244d81e2e473a60df4ac5e86`. Controlled fault cases are identified below. See the [earlier screen-by-screen audit](user-journey-audit.md) for the broader browser walk and large-library baseline.

## What works and where the release bar remains open

| Intended capability | Evidence from this pass | Remaining production work |
|---|---|---|
| Record a real execution and preserve failure | Installed browser and CLI captured actual local tools and an HTTP model interaction. Python exceptions and exit codes were exercised. | Durable incomplete captures under worker or host loss. Explicit coverage of native I/O, new adapters, and original workload scale. |
| Verify faithfully offline | On controlled run `dbb297102200`, capture reached the independent HTTP service once and **100 replays added zero requests**. Stopped-early, changed outcome and changed source cases failed. Separate real Ollama run `3b240aac5bf7` replayed 20/20. Its independent Git-output validator rejected the extra prose in the model response. | Repeat across live Groq, Gemini, NVIDIA and xAI, streaming, retries and concurrency. Qualify total offline isolation with an OS-isolated runner and independently monitored effects. |
| Compare and localize | Compared identical, different-shape and final-outcome-only cases in the CLI or browser. Hash-chain errors identify the affected boundary. | Real pairs labeled before seeing the diagnosis, alignment ambiguity and large divergent pairs. Earliest observed difference cannot establish causality by itself. |
| Inspect state | Inspected real captured values, fingerprint and CLI step state. Entry-point source change was refused. | Long-run independent state reconstruction checks and actual TUI, Perfetto and OTel viewer acceptance on the release build. Reconstructed state is the captured/declared state. |
| Fork what-if | In a controlled manifest task, fork `b068465d1c6d` replaced one recorded read. The failed parent stayed intact. The child matched the healthy run and an independent read of the real manifest. | Naturally occurring real agent failure with verified recovery, richer permitted-tool policies, and browser fork creation. The forked read was playback. |
| Storage and interop | The final wheel reopened existing runs. Perfetto and OTLP JSON exported from the real Ollama recording, and the reimported OTLP trace was flagged observational. | View in real collector and trace tools, full old-bundle and migration compatibility, recovery matrix, checksummed backups and independently witnessed rollback. |
| User and developer experience | Chrome walked capture, replay, inspect, compare, providers and corpus audit. CLI recorded, inspected, compared, forked, exported and imported. | Independent developer beta, browser download completion, accessibility at production scope, cross-platform installs and a real gallery. |
| Performance | Candidate handled 300 local read requests across list, detail and jobs with 12 concurrent workers and zero errors. p95 was 40.23 ms list, 41.11 ms detail and 33.29 ms jobs. These ran against a three-run workspace. | Soak, sustained reads/writes, large comparisons and imports, retention, resource ceilings and capture overhead across representative agents and machines. |
| Fleet and evaluation | Code paths exist. The stored evidence still includes synthetic fixtures and controlled local experiments. | Real fleet, holdout labels, blinded baseline, quality metrics and an independent evaluation against the original M5 gate. |
| Deployment and privacy | Local trusted-workspace execution, checksummed transport format and known-pattern redaction are present. | Public hosting needs identity, scoped authorization, user data boundaries, isolated execution, file/network/resource limits, durable job supervision and reviewed operations. The known-pattern scan cannot certify redaction completeness. |

The checked-in acceptance ledger at the baseline contained 147 rows, with 134 pending and 13 blocked. This scoped audit adds evidence for specific paths and leaves the six-month sign-off ledger open. No hosted inference or network-isolated multi-user staging was run in this pass.
