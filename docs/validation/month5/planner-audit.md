## How to read the result

Synthetic purity means the three planted families did not mix. It does not mean a
production failure has been root-caused. `fr match` says that in its
`qualification` field.

## Hardening and reproducible acceptance

The synthetic classifier fixture no longer appends the target family name to its
input text. It uses captured event features plus a neutral sample identifier;
regressions check that neither `family-` nor the target label enters that input.
The [software validation report](software-validation.json) is generated by
`examples/month5_failure_intelligence.py`, and the dedicated Month 5 workflow
runs the clustering, query, classifier and zero-cost policy gates on every PR.

To collect a genuinely blinded baseline, use:

```bash
fr train-classifier reviewed-rows.json --output private-classifier.json
fr baseline-inputs reviewed-rows.json private-classifier.json blinded-inputs.json
# Give only blinded-inputs.json to the baseline inference runner.
# Save its predictions with provider/model/prompt_sha256 provenance, then score:
fr compare-baseline private-classifier.json baseline-predictions.json
```

The export is bound to the dataset hash and exact held-out IDs. It includes event
text and the taxonomy, but excludes expected labels and classifier predictions.
Keep the answer-bearing report separate, freeze the baseline before scoring, and
retain the request/response provenance. The tooling does not invent baseline
predictions or treat a majority-class comparison as a prompted-model comparison.

Merging this software does not attest M5.1/M5.2/M5.4 production acceptance. Those
still require reviewed real failures, independently collected baseline predictions,
and the actual 672-tool corpus. No such production corpus is included in the repo.
